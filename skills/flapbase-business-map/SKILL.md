# 事業マップを作る

## 用意するもの

使ってよい事業の記録と、いま困っていることを用意する。

## 始める前に

すでにある記録から、事実・仮説・未確認を分ける。

## 手順

マーケティングの標準的な方法を、やさしい言葉で使う。分析の枠組みを順番にすべて埋めるのではなく、問いに合うものだけを選んで使う。

### 1. 状況を読む（フォームなし）

プロジェクト概要・サイト・投稿と記事の記録・測定の記録・施策の洗い出し（flapbase-measures-inventory）から読み取る。Flapbase Cloud では `project_spec_get`・`site_audit`・`workflow_get`・`business_map_get` を使う。持ち主に聞くのは、確認が必要な数点だけにする。

### 2. 問いを1つに絞る

| いま起きていること | 使う分析 |
| --- | --- |
| お客さまが少ない | 市場の大きさ・知られている度合い・お客さまが集まるまでの流れ |
| 売れてもお金が残らない | 値段・原価・お客さま1人を得る費用・回収にかかる月数 |
| 競合に選ばれない | お客さま・競合・自分／商品・値段・届け方・知らせ方 |
| 問い合わせは増えたが、契約に至らない | 問い合わせ後の対応・提案・成約までの流れ |
| 伸びが止まった | 事業の成長の度合い・常連のお客さま・隣接する市場 |

### 3. 分析の決まり

- お客さま・競合・自分（3C）：狙うのは「お客さまが求めていて、自分が応えられて、競合が十分に満たしていない部分」。3つの円が重なる真ん中ではない。
- 市場の特徴（競合が多く混んでいる／まだ知られていない）と、市場の成長の度合いは、戦略の仮説として出す。「伸びている市場だから広告を出す」のように機械的に決めない。
- 市場の大きさは、お客さまになりうる人の数 × 買う回数 × 単価で求め、数え方と前提を書く。シェア（占める割合）には、何を全体としたかも書く。
- お金の見方：お客さま1人を得る費用（広告以外も含む）・1人から得られる粗利・広告費1円あたりに戻る売上・回収にかかる月数。小規模な事業では「実際にいくら残るか」を先に見る。お客さまが少ないうちは、確定した値として扱わない。
- すべての所見と数字に、根拠の種類（実測・外部の情報・推定・仮説）を付ける。
- 専門用語（CAC・LTV・ROAS など）は添える程度にとどめ、本文はやさしい言葉で書く。

### 4. 地図に置く

結果は、決まった項目に分けて保存する（HTML は作らない）。項目は、いまの状況・問い・所見（根拠の種類つき）・数字・目指す状態・いま進めること。
- Flapbase Cloud では `business_map_publish` を使う。返ってきた URL を「Flapbase Cloud で見る」として持ち主に示す。途中の段階で保存してもよい。
- 目標や施策を変える内容は、持ち主の確認に回す。決めるのは人。
- 手元だけで使うときは、同じ内容を JSON で書き、必要なら1ページの HTML にする。何も外へ送らない。

### 5. 施策にして、結果を測る

- 所見から施策を1〜3つ提案し、改善できる余地の幅を見積もる（Flapbase Cloud の `improvement_estimate`）。
- 持ち主が選んだ施策は、ワークフローにする（テーマごとのスキルを使う）。2つの案を比べたいときは flapbase-split-test を使う。
- 測った結果で事業マップを直す。数字の更新はエージェントが行い、戦略を変えるかどうかは持ち主が決める。

### 専門家の診断を受ける（選べる）

課題が絞れないときや、施策の優先順位を決められないときは、Flapbase Cloud の Business の支援担当者に同じ事業マップを見てもらえる（https://flapbase.com/business）。持ち主にフォームは書かせず、事業マップと Project の記録を材料にする。

## チェックリスト

手順で確かめた項目を「確認済み」「未確認」「持ち主の判断待ち」に分けて書き出し、抜けがないかを確かめる。

## 終わりの目安

問い・根拠・仮説と、次に試す施策が、互いに対応している。

## 次にできること

flapbase-measures-inventory で、施策の余地を整理する。

## Flapbase で続ける

[Flapbase で開く](https://flapbase.com/skills/business-map)。公開されているスキルのページにある「エージェントで使う」で、手順と使う道具を確かめてから続ける。このスキル専用のワークフローはなく、Project も自動では作られない。手元の結果は自動では送られない。続ける範囲と持ち込む材料を、人が確かめてから進める。
