# 事業の地図を作る

正統なマーケティングの方法を、やさしい言葉で使う。フレームワークを順に埋めるのでなく、問いに合う物だけを呼ぶ。

## 1. 状況を読む（フォームなし）

プロジェクト概要・サイト・投稿と記事の記録・測定の記録・施策の棚卸し（flapbase-measures-inventory）から読む。Flapbase Cloud なら `project_spec_get`・`site_audit`・`workflow_get`・`business_map_get`。持ち主に聞くのは、確かめが要る数個だけ。

## 2. 問いを1つに絞る

| いま起きていること | 呼ぶ分析 |
| --- | --- |
| お客さまが少ない | 市場の大きさ・知られている度合い・集客の流れ |
| 売れても残らない | 値段・原価・1人を得る費用・回収の月数 |
| 競合に選ばれない | お客さま・競合・自分／商品・値段・届け方・知らせ方 |
| 問い合わせは増えたが決まらない | 受け皿・提案・成約の流れ |
| 伸びが止まった | 成長の段階・常連・隣の市場 |

## 3. 分析の決まり

- お客さま・競合・自分（3C）：狙うのは「お客さまが求めていて、自分が応えられて、競合が十分に満たしていない所」。3つの円の真ん中ではない。
- 市場の型（混んでいる／まだ知られていない）と成長の段階は、戦略の仮説として出す。「伸びている市場だから広告」のように機械的に決めない。
- 市場の大きさは掛け算（お客さまになりうる人の数 × 買う回数 × 単価）で、定義と前提を書く。シェアは分母を書く。
- お金の見方：1人を得る費用（広告以外も含む）・1人から得られる粗利・広告1円で戻る売上・回収の月数。小さな事業には「実際にいくら残るか」を先に。お客さまが少ないうちは確定値にしない。
- すべての所見と数字に根拠の種類を付ける：実測・外部の情報・推定・仮説。
- 専門の用語（CAC・LTV・ROAS など）は添えるだけ。主はやさしい言葉。

## 4. 地図に置く

結果は構造化して置く（HTML を作らない）：いまの状況・問い・所見（根拠の種類つき）・数字・目指す状態・いま進めること。
- Flapbase Cloud：`business_map_publish`。返った URL を「Flapbase Cloud で見る」として持ち主に示す。途中でも置いてよい。
- 目標や施策を変える中身は、持ち主の確認に回る。決めるのは人。
- 手元だけ：同じ中身を JSON に書き、必要なら1枚の HTML に描く。何も外へ送らない。

## 5. 施策へ、そして測る

- 所見から施策を1〜3つ提案し、改善余地の幅を試算する（Cloud の `improvement_estimate`）。
- 持ち主が採った施策をワークフローにする（テーマの skill へ）。比べたいときは flapbase-split-test。
- 測った結果で地図を直す。数字の反映はエージェントが行い、戦略を変えるかは持ち主が決める。

## 専門家の診断を受ける（選べる）

課題が絞れないとき、施策の優先が決められないときに、Flapbase Cloud の Business の支援担当者に同じ地図を見てもらえる（https://flapbase.com/business）。持ち主にフォームは書かせず、地図と Project の記録を材料にする。
