# 今のサイトを Flapbase Site に移す

## 用意するもの

元のサイトのコード・画像と、移行するページを用意する。

## 始める前に

元の見え方、使える Site の部品、移せない要素を確かめる。

## 手順

移す作業をするのはエージェント。元の文章・画像・セクションの構成を Site の部品に置き換え、公開前の下書きとして人に渡す。

### 元のページと部品を読む

1. 文章と画像を移す権利を、人が確かめていることを確認する。対象のページと、残したい内容・動きを整理する。
2. 元のコードを手元で開く。React・Astro などビルドが要るものは、そのサイトの手順でビルドする。各ページをスマホ幅と PC 幅で描き、画像を保存する。見た目だけでなく、リンク・メニュー・フォームなどの動きも確認する。
3. ページごとに、ヘッダー・最初に見える部分（FV）・特徴・実績・料金・FAQ・問い合わせ・フッターなどのセクションに分け、順序・文章・画像・リンク先を控える。
4. `workspace_projects_list` で移行先を選ぶ。返った id を `projectId` に渡し、`site_catalog` で、テンプレート・セクション・要素の部品と、使える操作・変更できる項目を読む。人が画面でしか行えない項目も確認する。
5. 「元のページとセクション／使う Site の部品／文章・画像・リンクと変更する項目／再現できない部分」の対応表を作る。部品名と操作はカタログにあるものだけを使い、見た目を完全に再現できるとは約束しない。

### 下書きに移す

1. 新規なら `site_create` に `projectId`・`templateId`・`name`・操作ごとの UUID `idempotencyKey` を渡す。既存なら `site_get` に `projectId`・`artifactId` を渡す。以後は返った Site の id と版を使う。画像の送信にも `artifactId` が要るので、先に下書きを用意する。
2. 使う画像を `site_image_upload` で準備する。`projectId`・`artifactId` と、image に media・bytes・sha256 を渡す。PNG・JPEG・WebP、8MB まで、1辺 8192px・1600万画素まで。sha256 は sha256: と16進64字。upload.stored が false なら、返った upload.command に従い15分以内にファイルを PUT で送る。返った image（ref・digest・media）をそのまま操作に使う。
3. 対応表に沿って `site_apply` の operations と content を組む。`projectId`・`artifactId`・`expectedRevisionId` と操作ごとの UUID `idempotencyKey` を渡し、まず `check: true` で検査する。1回の operations は100件以内。エラーの操作番号・パス・理由を見て直す。
4. 検査が通ったら check を外し、同じ入力と `idempotencyKey` で保存する。次の変更には保存後の版を使う。版が衝突したら `site_get` で読み直し、他の変更を保って組み直す。リンクとページの対応を残し、旧 URL の転送が必要ならカタログの content の項目で扱う。

### 元の画面と比べる

1. `site_render` に `projectId`・`artifactId` と保存した `revisionId` を渡す。返った HTML と実測スクリプトを手元のブラウザで実行する。各ページを元の画面と同じ幅で描き、セクションの順序・FV の構成・文章・画像・余白・リンクを比べる。
2. `site_compare` には同じ版と `referenceStructure`（sections は対応するセクションの部品名の配列、hero は FV の部品名）を渡す。この道具は、Site に登録済みの参考画像を使って比べる。元の画像を直接渡すことはできない。参考画像がなくてエラーになったときは、その旨を記録し、手元で元の画像と見比べる。登録済みの画像があっても、元の画面のものか確かめる。この道具が行うのは構造の比較で、ピクセル単位の比較はしていないので、そう報告する。
3. 差があれば `site_apply` の検査・保存からやり直す。描画・比較・修正は各ページで最大3回。上限に達したら残る差を人に渡し、繰り返さない。
4. 最後に `site_check` で保存した版を点検する。静的な検査だけでは、実際の表示を測ったことにならない。手元のスクリプトでスマホと PC の文字サイズ・横のはみ出し・押せる大きさ・リンクを確かめる。使い終わったブラウザと自分が立てたサーバーは閉じる。

### 人に返す

- 下書きの id と版、対応表、比較した画像、検査結果と未確認の部分を渡す。
- Site の部品に当てはまらなかった JavaScript の動き・カルーセル・タブ・任意の HTML などと、移さなかった文章・画像・ページ・フォームの処理・外部連携を一覧にする。代わりの部品で組んだ部分と残る見た目の違いも示す。
- 公開は `site_publish_request` に対象の `projectId`・`artifactId`・`expectedRevisionId` と新しい UUID `idempotencyKey` を渡して人に頼む。承認待ちであり、公開は人が Site の画面で決める。

### 守ること

- 任意の HTML や外部スクリプトを持ち込まない。Site にそのセクションはない。埋め込みもカタログで認められた種類だけを使う。
- 秘密・個人情報・問い合わせの中身を、画像・本文・MCP の入力・記録に送らない。
- `site_render`・`site_compare`・`site_check` は既定では手元で描き、クレジットを使わない。手元で描けず `serverRender: true` が要る場合は、1呼び出し1クレジットとして予定回数と合計の見積りを先に人に示し、承認された範囲だけ実行する。画像生成など別のクレジットを使う道具も、先に見積りを人に見せる。入力定義にない同意の引数は足さない。

## チェックリスト

手順で確かめた項目を「確認済み」「未確認」「持ち主の判断待ち」に分けて書き出し、抜けがないかを確かめる。

## 終わりの目安

下書きと元の表示の比較結果、移せない部分を人に返した。

## 次にできること

flapbase-publish-work で下書きの確認を頼む。

## Flapbase で続ける

[Flapbase で開く](https://app.flapbase.com/start?from=skill:flapbase-site-migrate)。既存ワークフローから、対象の Project を選ぶか新しく作って始める。手元の結果は自動では送られない。続ける範囲と持ち込む材料を人が確かめてから進める。
