# AI の答えに出るかを見る

サイトの診断の続き。並びは次のとおり。
1. flapbase-site-check：サイトの形（手元・何も送らない）
2. flapbase-site-diagnosis：サイトの中身（AI 自身が答える）
3. **この skill：外での見え方（AI の答えに名前が出るか・正しいか）**
4. 足りない答えは flapbase-article-acquisition で記事に、一覧に載っていなければ紹介を頼む

## 決まり

- 確かめるのは、ログアウトしたプライベートの窓で。自分のアカウントの答えは、自分に合わせて変わる。
- 1回の答えで結論を出さない。同じ質問を同じ順で続けて記録する。
- 自分で作る「おすすめの一覧」で自分を1位にしない。自分の売り込みは「自分と競合の比べ」「競合の代わり」の頁で。
- 推測で事実を書かない。分からない所は「不足」と書く。
- まだ発表されていない機能や仕組みを前提にしない。

## 1. 事業の事実を1枚にまとめる

何を売るか（1文、飾りなし）・だれ向けか、だれ向けでないか・すべての商品と値段・買う前の質問10個と2行の答え・やらないこと・解約や返品の条件。サイトから読める物だけを使い、ない物は「不足」と、それを書くべき頁を添える。不足が To-do になる。
- Flapbase Cloud につないでいれば `project_spec_get` と `site_get` から組み、不足は `project_spec_propose` で持ち主の確認に回す。

## 2. 買う前の質問を決めて、毎週記録する

10問を固定する：「◯◯の場面で一番よい（分類）は」3・「（競合）の代わり」2・「（自分）の評判」2・「（自分）と（競合）の比べ」2・「（分類）の値段」1。お客さまの言葉で。
記録の欄：日付・質問・名前が出たか・何番目か・出典・値段を何と言ったか・直すべき誤り。
- Cloud なら測定の工程の記録（`work_item_note`）に残し、事業の地図の数字に「AI の答えで名前が出た回数」として置く（`business_map_publish`）。

## 3. 自分について何と言われているか

「（自分）について知っていること」「（自分）の評判」を聞き、答えの事実ごとに 正しい・誤り・古い・確かめられない を付ける。
- 自分のサイトが誤りの出どころ → その頁を直す。
- 他人の頁が出どころ → 書き手に正しい事実と確かめ方を送る（送るのは持ち主）。
- 第三者の評判がない → それが一番の空き。
- 同じ名前のほかの事業と混ざっていないか、答えのドメインを必ず見る。

## 4. 比べる検索と、だれの一覧に載っているか

AI は長い質問を短い検索（一番よい・代わり・評判・値段・比べ）に分けて調べる。自分の分類で15の検索を作り、検索して、上位にある一覧の書き手と、自分が載っているかを表にする。
- Cloud なら `topics_list`・`topic_search` で関係する話題を集め、載りたい一覧は Inbox（`idea_add`）へ。

## 5. 値段と受け皿を、AI が読める形に

- 値段・できること・できないこと・だれ向けでないか を、スクリプトなしの HTML の文で書く（ソースを表示して値段の文字があるか確かめる）。
- robots.txt で検索用のクローラーを止めていないか確かめる。学習用を断るかは持ち主の選択。
- Flapbase の Site は公開を静的な HTML で出すので、文で書けばそのまま読まれる。点検は `site_audit`。

## 6. 回し方

- 毎週：決めた質問のうち3〜5を聞いて記録 → 1つだけ直す（誤り・不足・載りたい一覧）。
- 毎月：自分についての2問を最後まで読む → 比べる検索の表を作り直す。
- 改善余地は `improvement_estimate` で幅を見て、施策は事業の地図（flapbase-business-map）に置く。

## 専門家の診断を受ける（選べる）

答えに誤りが多いとき、どこから直すか決められないときに、Flapbase Cloud の Business の支援担当者に見てもらえる（https://flapbase.com/business）。持ち主にフォームは書かせず、この記録と Project の情報を材料にする。
