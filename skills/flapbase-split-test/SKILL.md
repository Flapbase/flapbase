# 比べて試す

## 用意するもの

比べたい施策と、使える期間・数字を用意する。

## 始める前に

数字の量と、同時比較か前後比較か、変える項目を確かめる。

## 手順

一つの施策だけでは良し悪しが分からない。比べる相手を作って試す。

### 1. 規模を見る

持ち主が見せた数字（表示・来訪・問い合わせなど）から、1案あたりどれだけ数が集まるかを見る。
- **十分**（1案あたり数百以上の表示や来訪が、2〜4週間で見込める）：同じ期間に2案を並べる（A/B）。
- **少ない**：前後で比べる（季節・曜日・特別な出来事による違いも書き添える）か、見出しや申し込み先の案内のように、差が大きく出やすいものだけを試す。
- 足りないときは「この数字では差を見分けられない」と先に言う。

### 2. 設計

- 仮説：何を変えると、どの数字が、なぜ動くか。
- 変えるものは1つ（見出し・画像・案内の文・申し込み先・送る時刻など）。
- 測る数字を1つ決める（問い合わせ・予約・保存・クリック）。
- 期間と、止める条件（数が集まった・期限が来た）を先に決める。
- Flapbase Cloud に接続していれば、`workflow_create` で試しのワークフローにし、2案は Design・Publish・Site の版として作る。

### 3. 実施と判定

- 期間中は案を直さない。
- 判定は4つ：勝ち・負け・差なし・数が足りない。差が小さいときに勝ちと言わない。
- 結果・数字・期間・気づきを残す（Cloud なら `work_item_note`）。

### 4. 次の施策に生かす

- 結果を、施策の一覧（flapbase-measures-inventory）の該当する項目に記録する。
- 「差なし」「数が足りない」も残す。同じ試しを繰り返さないため。
- 次の施策の試算と提案に使う。

### 決まり

- お客さまに不利な比べ方（一方だけ価格を偽るなど）をしない。
- 広告や表示の決まりに触れる試し（値引きの見せ方など）は、持ち主に確かめてから。

## チェックリスト

手順で確かめた項目を「確認済み」「未確認」「持ち主の判断待ち」に分けて書き出し、抜けがないかを確かめる。

## 終わりの目安

勝ち・負け・差なし・数が足りない、の判定と根拠を残した。

## 次にできること

flapbase-measures-inventory に次の施策を反映する。

## Flapbase で続ける

[Flapbase で開く](https://flapbase.com/skills/split-test)。公開のスキルのページの「エージェントで使う」で、手順と使う道具を確かめて続ける。専用ワークフローや Project の自動作成はない。手元の結果は自動では送られない。続ける範囲と持ち込む材料を人が確かめてから進める。
